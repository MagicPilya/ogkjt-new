# Миграция Strapi: SQLite → MySQL (пошагово)

## Что нужно

- На сервере (cPanel) уже созданы: база MySQL, пользователь с полными правами на эту базу.
- В Node.js приложении (api.ogkjt.by) заданы переменные окружения для MySQL.

---

## Шаг 1. Где смотреть логи (ошибка 500)

Путь `~/logs/nodejs/error.log` на твоём хостере может отсутствовать. Проверь:

```bash
# Варианты расположения логов
ls -la ~/logs/
ls -la ~/nodejs/
# Логи приложения в cPanel: «Node.js приложения» → выбери приложение → вкладка «Журналы» / «Logs»
# Или в корне приложения после запуска:
ls -la /home/ogkjtby/apps/ogkjt-api/*.log 2>/dev/null
```

Если найдёшь лог — в момент нажатия «Сохранить»/«Опубликовать» выполни `tail -f путь/к/лог-файлу` и пришли последние строки с ошибкой.

---

## Шаг 2. Проверить переменные окружения на сервере

В cPanel → **Node.js приложения** → твоё приложение (api.ogkjt.by) → **Environment Variables** должны быть:

| Переменная | Пример значения | Обязательно |
|------------|-----------------|-------------|
| `DATABASE_CLIENT` | `mysql` | да |
| `DATABASE_HOST` | `localhost` | да |
| `DATABASE_PORT` | `3306` | да |
| `DATABASE_NAME` | имя базы (например `ogkjtby_api`) | да |
| `DATABASE_USERNAME` | пользователь БД | да |
| `DATABASE_PASSWORD` | пароль пользователя БД | да |
| `STRAPI_PUBLIC_URL` | `https://api.ogkjt.by` | да |

Имена баз и пользователей в cPanel часто с префиксом (например `ogkjtby_api`). Проверь в **MySQL® Databases**, что база и пользователь созданы и пользователь привязан к базе с полными правами (All Privileges).

---

## Шаг 3. Создание таблиц в MySQL (первый запуск)

Strapi при первом запуске с пустой MySQL-базой сам создаёт таблицы по схемам контент-типов. Миграции в папке `database/migrations` у тебя не используются — всё идёт через автосоздание.

**3.1. Убедиться, что на сервере используется MySQL**

- В env приложения обязательно `DATABASE_CLIENT=mysql` и все переменные из шага 2.
- Перезапусти приложение (в cPanel: «Restart» у Node.js приложения).

**3.2. Проверить, что таблицы появились**

Зайди в cPanel → **phpMyAdmin** (или MySQL по SSH), выбери свою базу и посмотри список таблиц. После успешного старта Strapi должны появиться таблицы вроде:

- `strapi_core_store_settings`
- `globals` (для single type api::global.global)
- `globals_localizations_ln`
- таблицы для других типов контента, компонентов, админки и т.д.

Если таблиц нет — приложение при старте не смогло подключиться к БД или создать схему. Тогда снова проверь логи (шаг 1) и переменные (шаг 2).

---

## Шаг 4. Если таблицы есть, но 500 при сохранении/публикации

Возможные причины:

1. **Права пользователя БД**  
   В cPanel для пользователя этой базы должны быть права: **ALL PRIVILEGES** (или как минимум SELECT, INSERT, UPDATE, DELETE).

2. **Несовпадение схемы**  
   Если база была создана вручную или из старого бэкапа, структура может не совпадать со схемой Strapi. Тогда безопасный вариант — создать **новую пустую базу**, в env прописать её имя, перезапустить Strapi и дать ему заново создать все таблицы. Старую базу потом можно удалить.

3. **Ошибка в коде/плагине**  
   Точный ответ даст только стек из лога (шаг 1). Можешь прислать фрагмент лога — подскажу, что менять.

## Шаг 5. Перенос данных из SQLite в MySQL (если нужны старые данные)

У тебя раньше был SQLite (`.tmp/data.db`). Strapi не умеет автоматически «перелить» SQLite → MySQL одной кнопкой. Варианты:

**Вариант A: Настроить заново только Global (и мало контента)**  
- После миграции таблиц (шаг 3) зайти в админку и заново заполнить single type «Global» и остальное. Данные с фронта (web.ogkjt.by) тогда будут браться уже из MySQL.

**Вариант B: Выгрузить из старого Strapi (SQLite) и загрузить в новый (MySQL)**  
- Локально один раз поднять Strapi с SQLite (указать в `.env` старый `DATABASE_CLIENT=sqlite` и путь к `data.db`).
- Через админку или API экспортировать контент (Content-Type Builder / Export или плагины экспорта).
- Поднять Strapi с MySQL (новая база) и импортировать контент туда.  
Это уже отдельная настройка под твой объём данных; если контента немного, чаще проще ввести заново (вариант A).

**Вариант C: Ручной перенос только таблицы `globals`**  
- Если нужны только глобальные настройки: экспортировать из SQLite строки из таблицы, которая соответствует single type global, и вставить их в MySQL в таблицу `globals` (и связанные локализации), соблюдая форматы и ID. Требует аккуратности и понимания структуры.
