ЧАСТЬ 1. ПРОИЗВОДСТВЕННАЯ ПРАКТИКА

1.1. Цели и задачи производственной части практики

Производственная практика является важным этапом подготовки специалиста в области информационных технологий, позволяющим применить полученные теоретические знания в реальных условиях профессиональной деятельности. В рамках преддипломной практики на базе Оршанского колледжа – филиала учреждения образования "Белорусский государственный университет транспорта" была поставлена задача реализации веб-сайта образовательного учреждения с использованием современных технологий веб-разработки.

Основной целью производственной части практики являлась реализация и настройка веб-сайта колледжа на основе спроектированной архитектуры. Данная цель предполагала выполнение комплекса работ, направленных на создание функционального веб-ресурса, обеспечивающего информационную открытость образовательного учреждения и удобство взаимодействия с различными категориями пользователей.

В процессе достижения поставленной цели решались следующие задачи. Первоочередной задачей являлся анализ требований к веб-сайту и проектирование его структуры. Необходимо было определить основные разделы сайта, их назначение и взаимосвязи, спроектировать пользовательские сценарии взаимодействия с ресурсом, определить требования к функциональности и контенту.

Следующей важной задачей было освоение современных технологий веб-разработки, в частности фреймворка Next.js для клиентской части и системы управления контентом Strapi для бэкенда. Требовалось изучить возможности данных технологий, их особенности интеграции, освоить практические навыки работы с ними.

Третьей задачей являлась разработка и доработка клиентской части сайта. Это включало создание страниц различных разделов, разработку переиспользуемых компонентов пользовательского интерфейса, реализацию навигации и структуры сайта, обеспечение адаптивности интерфейса для различных устройств.

Четвертой задачей была настройка системы управления контентом Strapi. Требовалось спроектировать и реализовать модели данных для различных типов контента, настроить API для взаимодействия с фронтендом, обеспечить возможность управления контентом через административный интерфейс.

Пятой задачей являлась интеграция фронтенда с бэкендом через REST API. Необходимо было реализовать механизмы получения данных из Strapi, обеспечить корректную обработку ответов API, реализовать кэширование и оптимизацию запросов.

Шестой задачей было наполнение сайта контентом. Требовалось подготовить и структурировать информационные материалы, разместить их в системе управления контентом, обеспечить корректное отображение контента на страницах сайта.

Важно отметить, что производственная практика является частью дипломного проекта, поэтому некоторые функции могут быть реализованы частично, а развертывание сайта на хостинге планируется в рамках дальнейшей работы над дипломным проектом. Однако выполнение перечисленных задач позволило создать работоспособный прототип веб-сайта, демонстрирующий основные возможности разрабатываемого решения.

1.2. Характеристика базы практики и проекта

База практики – Оршанский колледж – филиал учреждения образования "Белорусский государственный университет транспорта" – является образовательным учреждением среднего специального образования, осуществляющим подготовку специалистов для железнодорожной отрасли. Колледж имеет богатую историю и традиции, ведет активную образовательную и воспитательную деятельность, взаимодействует с различными категориями пользователей: абитуриентами, студентами, их родителями, работодателями, представителями общественности.

В современных условиях эффективное функционирование образовательного учреждения невозможно без наличия качественного веб-ресурса, обеспечивающего информационную открытость, удобство получения информации и взаимодействия с колледжем. Существующий веб-сайт колледжа требовал модернизации с точки зрения технологий, функциональности и пользовательского опыта.

Проект разработки веб-сайта колледжа представляет собой комплексное решение, включающее клиентскую часть на базе Next.js и серверную часть на базе Strapi. Выбор данного технологического стека обусловлен современными требованиями к веб-разработке, необходимостью обеспечения производительности, масштабируемости и удобства администрирования.

Next.js представляет собой React-фреймворк для производства, предоставляющий возможности серверного рендеринга, статической генерации страниц, оптимизации производительности. Использование Next.js позволяет создавать быстрые и оптимизированные веб-приложения с поддержкой современных стандартов веб-разработки.

Strapi является open-source headless CMS, предоставляющей RESTful API для управления контентом. Использование Strapi позволяет разделить логику управления контентом и представления данных, обеспечивая гибкость в разработке и возможность независимого развития фронтенда и бэкенда.

Структура разрабатываемого веб-сайта включает несколько основных разделов, представленных на рисунке 1.1. Шапка сайта состоит из двух уровней: первый уровень содержит логотип учреждения образования, поиск по сайту и версию для слабовидящих; второй уровень представляет главное меню навигации с разделами: Новости, О колледже, Абитуриентам, Обучающимся, Воспитательная работа, Одно окно, Электронные обращения.

Главная страница содержит Hero-блок с визуализацией фасада колледжа и основным названием, блок преимуществ и ключевых ценностей колледжа, блок "Актуальное" с новостями и календарем событий, а также плавающую панель быстрого доступа с динамически редактируемыми элементами.

Раздел "О колледже" включает подразделы: Администрация, Контакты и схема проезда, Государственные символы и символика колледжа, Профилактика коррупционных правонарушений, Платные услуги, История колледжа.

Раздел "Абитуриентам" содержит подразделы: Специальности, План приема, Документы для подачи в комиссию, Информация о свободных местах (перевод/восстановление).

Раздел "Обучающимся" включает информацию для дневного отделения (расписание занятий, графики образовательного процесса), заочного отделения (график сессий, объявления) и сведения об общежитии (новости общежития, правила проживания).

Раздел "Воспитательная работа" содержит подразделы: СППС (информация о психологе и социальном педагоге), Молодежная политика (БРСМ, Кодекс чести, кружки и секции), В помощь куратору.

Раздел "Одно окно" представляет собой посадочную страницу с информацией об административных процедурах и графике приема граждан. Раздел "Электронные обращения" обеспечивает возможность взаимодействия пользователей с администрацией колледжа через форму обращений.

Раздел "Новости" обеспечивает динамическое отображение новостных материалов с возможностью просмотра отдельных статей по уникальному идентификатору (slug).

Проект разрабатывался в локальной среде разработки с использованием современных инструментов: Node.js для выполнения JavaScript-кода, npm для управления зависимостями, Git для контроля версий. Развертывание на хостинге планируется в рамках дальнейшей работы над дипломным проектом.

1.3. Содержание выполненных работ в рамках производственной практики

1.3.1. Анализ требований и проектирование структуры сайта

Начальным этапом производственной практики являлся анализ требований к веб-сайту и проектирование его структуры. Данный этап включал изучение специфики работы образовательного учреждения, анализ потребностей различных категорий пользователей, определение функциональных требований к системе.

В процессе анализа требований были определены основные категории пользователей сайта. К первой категории относятся абитуриенты, которым необходима информация о специальностях, условиях поступления, необходимых документах. Ко второй категории относятся студенты, нуждающиеся в актуальной информации об учебном процессе, расписании, общежитии. К третьей категории относятся родители студентов, заинтересованные в информации о колледже, воспитательной работе. К четвертой категории относятся работодатели, ищущие информацию о выпускниках и возможностях сотрудничества. К пятой категории относятся представители общественности и СМИ, интересующиеся деятельностью колледжа. Категории пользователей и их основные потребности представлены на рисунке 1.3.1.

На основе анализа потребностей пользователей была спроектирована структура сайта, представленная на рисунке 1.1. Структура включает иерархическую организацию разделов с четким разделением по функциональному назначению. Каждый раздел имеет подразделы, обеспечивающие детализацию информации.

Проектирование пользовательских сценариев позволило определить основные пути взаимодействия пользователей с сайтом. Например, сценарий абитуриента включает просмотр информации о специальностях, изучение плана приема, ознакомление с необходимыми документами. Сценарий студента включает просмотр новостей, получение информации об учебном процессе, обращение в раздел "Одно окно".

На этапе проектирования были определены требования к функциональности сайта. Ключевыми требованиями являлись: обеспечение адаптивности интерфейса для различных устройств, поддержка динамического контента через CMS, обеспечение быстрой загрузки страниц, удобная навигация, поиск информации.

Результатом этапа анализа требований и проектирования стала техническая спецификация, включающая описание структуры сайта, пользовательских сценариев, требований к функциональности. Данная спецификация послужила основой для дальнейшей разработки.

1.3.2. Освоение технологий и настройка рабочего окружения

Важным этапом практики являлось освоение технологий веб-разработки, выбранных для реализации проекта. Основными технологиями являлись Next.js для клиентской части и Strapi для управления контентом.

Изучение Next.js включало освоение концепций серверных компонентов и клиентских компонентов, понимание различий между ними и правил их использования. Серверные компоненты выполняются на сервере и позволяют получать данные напрямую, не передавая их через клиент. Клиентские компоненты выполняются в браузере и используются для интерактивных элементов интерфейса.

Освоение Next.js также включало изучение механизмов маршрутизации на основе файловой системы, работы с динамическими маршрутами, использования серверных и клиентских функций получения данных. Особое внимание было уделено оптимизации производительности через использование статической генерации страниц и инкрементальной статической регенерации.

Изучение Strapi включало освоение концепций content types, components, relations, понимание структуры API, механизмов аутентификации и авторизации. Были изучены возможности настройки моделей данных, работы с медиафайлами, использования компонентов для переиспользования структур данных.

Настройка рабочего окружения включала установку Node.js версии, соответствующей требованиям используемых технологий, настройку менеджера пакетов npm, установку необходимых зависимостей проекта. Для фронтенда были установлены зависимости, перечисленные в таблице 1.1.

Настройка инструментов разработки включала конфигурацию TypeScript для обеспечения типобезопасности кода, настройку ESLint для контроля качества кода, настройку Prettier для единообразного форматирования. Была настроена интеграция с системой контроля версий Git.

Результатом этапа освоения технологий и настройки рабочего окружения стало готовое к разработке окружение с установленными и настроенными инструментами, а также базовое понимание используемых технологий, достаточное для начала разработки.

1.3.3. Разработка и доработка клиентской части сайта

Разработка клиентской части сайта осуществлялась с использованием Next.js и React. Архитектура клиентской части основана на компонентном подходе, обеспечивающем переиспользование кода и модульность разработки.

Структура клиентской части организована в соответствии с файловой системой маршрутизации Next.js. Страницы размещены в директории app, каждая страница представляет собой файл page.tsx. Динамические маршруты реализованы через директории с квадратными скобками в названии, например [slug] для страниц новостей.

Разработка началась с создания базовой структуры приложения, включающей корневой layout, обеспечивающий общую структуру всех страниц. Layout включает компоненты Header и Footer, которые отображаются на всех страницах сайта. Пример структуры layout представлен в листинге 1.1.

Листинг 1.1 – Структура корневого layout

```typescript
export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="ru">
      <body>
        <Header />
        <main>{children}</main>
        <Footer />
      </body>
    </html>
  );
}
```

Компонент Header реализует навигационное меню сайта с поддержкой многоуровневой структуры. Меню загружается из Strapi через API, что обеспечивает возможность управления структурой навигации без изменения кода. Для мобильных устройств реализовано выдвижное меню с использованием компонента Sheet из библиотеки Radix UI.

Компонент Footer содержит контактную информацию, ссылки на социальные сети, информацию о колледже. Данные также загружаются из Strapi, обеспечивая централизованное управление контактами.

Главная страница включает несколько блоков: Hero-секцию с основным сообщением, блок быстрых ссылок, сетку новостей, календарь событий. Каждый блок реализован как отдельный компонент, что обеспечивает модульность и возможность переиспользования.

Компонент NewsGrid реализует отображение списка новостей с пагинацией. Новости загружаются из Strapi через API с использованием серверных компонентов Next.js. Каждая новость отображается в виде карточки с изображением, заголовком, анонсом и датой публикации.

Компонент Events отображает предстоящие события из календаря. События фильтруются по дате, отображаются только будущие события, отсортированные по дате. Для каждого события отображается название, дата, место проведения, описание.

Разработка страниц разделов осуществлялась с учетом специфики каждого раздела. Страницы разделов "Абитуриентам", "Студентам", "О колледже" имеют подстраницы, реализованные через вложенную структуру директорий. Например, страница "Специальности" находится по пути /applicants/specialties.

Для страниц, контент которых управляется через Strapi, реализована загрузка данных через серверные компоненты. Например, страница новости загружает данные статьи по slug из URL, что обеспечивает динамическую генерацию страниц для каждой новости.

Разработка компонентов пользовательского интерфейса осуществлялась с использованием библиотеки компонентов на базе Radix UI и стилизации через Tailwind CSS. Созданы переиспользуемые компоненты: Button, Card, Input, Textarea, Dialog, NavigationMenu, Sheet, Calendar. Компоненты реализованы с поддержкой темной темы и адаптивности.

Адаптивность интерфейса обеспечивается через использование responsive-классов Tailwind CSS. Для различных размеров экранов применяются различные варианты отображения: на мобильных устройствах используется одноколоночная верстка, на планшетах – двухколоночная, на десктопах – многоколоночная с расширенными возможностями.

Оптимизация производительности реализована через использование статической генерации страниц, где это возможно, и инкрементальной статической регенерации для динамического контента. Изображения оптимизируются через встроенный компонент Image Next.js, обеспечивающий lazy loading и автоматическую оптимизацию размеров.

Результатом этапа разработки клиентской части стало создание функционального интерфейса сайта с поддержкой всех основных разделов, адаптивным дизайном, интеграцией с бэкендом через API.

1.3.4. Настройка и использование Strapi для хранения контента

Настройка системы управления контентом Strapi включала проектирование моделей данных, настройку API, конфигурацию административного интерфейса. Модели данных спроектированы с учетом требований к контенту сайта и особенностей работы образовательного учреждения.

Основной моделью данных является Article (Новость), предназначенная для хранения новостных материалов. Модель включает поля: title (заголовок), slug (уникальный идентификатор для URL), announcement (анонс), content (основное содержимое в формате blocks), cover (обложка), date (дата публикации). Схема модели Article представлена в листинге 1.2.

Листинг 1.2 – Схема модели Article

```json
{
  "kind": "collectionType",
  "collectionName": "articles",
  "attributes": {
    "title": {
      "type": "string",
      "required": true
    },
    "slug": {
      "type": "uid",
      "targetField": "title"
    },
    "announcement": {
      "type": "text",
      "required": true
    },
    "content": {
      "type": "blocks"
    },
    "cover": {
      "type": "media",
      "multiple": false,
      "allowedTypes": ["images"]
    },
    "date": {
      "type": "date"
    }
  }
}
```

Модель Event (Событие) предназначена для хранения информации о событиях колледжа. Модель включает поля: title (название), date (дата и время), location (место проведения), description (описание в формате blocks), file (прикрепленный файл). Схема модели Event представлена в листинге 1.3.

Листинг 1.3 – Схема модели Event

```json
{
  "kind": "collectionType",
  "collectionName": "events",
  "attributes": {
    "title": {
      "type": "string",
      "required": true
    },
    "date": {
      "type": "datetime",
      "required": true
    },
    "location": {
      "type": "string"
    },
    "description": {
      "type": "blocks"
    },
    "file": {
      "type": "media",
      "allowedTypes": ["files"]
    }
  }
}
```

Модель Page (Страница) предназначена для хранения контента статических страниц. Модель включает поля: title (заголовок), slug (уникальный идентификатор), content (содержимое в формате blocks). Данная модель позволяет управлять контентом страниц через административный интерфейс без изменения кода.

Модель Global (Глобальные настройки) представляет собой single type, предназначенный для хранения глобальных настроек сайта. Модель включает поля: mainMenu (главное меню, компонент), address (адрес), phoneReception (телефон приемной), phoneDirector (телефон директора), email (электронная почта), instagramLink, telegramLink, tiktokLink (ссылки на социальные сети). Схема модели Global представлена в листинге 1.4.

Листинг 1.4 – Схема модели Global

```json
{
  "kind": "singleType",
  "collectionName": "globals",
  "attributes": {
    "mainMenu": {
      "type": "component",
      "repeatable": true,
      "component": "elements.menu-section"
    },
    "address": {
      "type": "string"
    },
    "phoneReception": {
      "type": "string"
    },
    "email": {
      "type": "email"
    }
  }
}
```

Для структурирования меню созданы компоненты MenuSection и MenuLink. Компонент MenuSection включает поля: title (название раздела), url (ссылка раздела), links (массив ссылок подразделов). Компонент MenuLink включает поля: title (название ссылки), url (URL ссылки). Использование компонентов позволяет гибко настраивать структуру меню через административный интерфейс.

Настройка API включала конфигурацию endpoints для каждой модели данных. Strapi автоматически генерирует REST API endpoints для каждой collection type, обеспечивая стандартные операции CRUD (Create, Read, Update, Delete). Для single type генерируется один endpoint для получения и обновления данных.

Настройка прав доступа осуществлялась через роли и права в Strapi. Для публичного доступа к контенту настроена роль Public с правами на чтение данных. Для административного доступа используется роль Authenticated с полными правами на управление контентом.

Конфигурация CORS настроена для разрешения запросов с фронтенда. В файле конфигурации указан origin фронтенда, разрешены необходимые HTTP-методы (GET, POST, PUT, DELETE), настроены заголовки запросов.

Наполнение сайта контентом осуществлялось через административный интерфейс Strapi. Были созданы записи новостей, событий, настроено главное меню, заполнены глобальные настройки. Контент структурирован в соответствии с требованиями образовательного учреждения.

Результатом этапа настройки и использования Strapi стало создание полнофункциональной системы управления контентом с настроенными моделями данных, API endpoints, административным интерфейсом, наполненной актуальным контентом.
